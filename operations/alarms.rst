Alarms
======

|OpAla|

Overview
--------

The Alarms section provides a centralized view for monitoring, filtering, and managing operational alarms generated by the |morpheus| appliance and its managed infrastructure. Alarms are triggered by health checks, threshold violations, integration failures, and other operational events that require administrator attention.

Navigate to Operations > Alarms to access the alarm management interface.

Alarm List
----------

The alarm list displays all current alarms matching the active filters. Each alarm entry shows:

- **Alarm Name/Message** — A description of the condition that triggered the alarm
- **Category** — The alarm category (e.g., Cloud, Instance, Appliance, Integration)
- **Status** — The current alarm state (Open, Acknowledged, Closed)
- **Severity** — The severity level of the alarm
- **Date Created** — When the alarm was first triggered
- **Last Updated** — When the alarm state last changed

Filtering Alarms
-----------------

Use the filter controls at the top of the alarm list to narrow displayed alarms:

ALARM STATUS
  Filter by alarm state:

  - **Open** — Active alarms requiring attention (default view)
  - **Acknowledged** — Alarms that have been acknowledged but not yet resolved
  - **Closed** — Resolved or auto-cleared alarms

ALARM CATEGORY
  Filter alarms by their source category:

  - **Cloud** — Alarms related to Cloud integration health
  - **Instance** — Alarms related to managed Instance health
  - **Appliance** — Alarms related to the |morpheus| appliance itself
  - **Integration** — Alarms related to third-party integration connectivity
  - **Infrastructure** — Alarms related to hosts, networks, or storage

SEARCH
  Free-text search across alarm names and descriptions.

Managing Alarms
---------------

Acknowledging Alarms
^^^^^^^^^^^^^^^^^^^^

Acknowledging an alarm indicates that an administrator is aware of the issue and is investigating or has determined no immediate action is needed:

#. Select one or more alarms from the list
#. Click the :guilabel:`ACKNOWLEDGE` button (or use the row-level action)
#. The alarm status changes to **Acknowledged**

To un-acknowledge an alarm (return it to Open status):

#. Select the acknowledged alarm
#. Click :guilabel:`UNACKNOWLEDGE`
#. The alarm returns to **Open** status

Viewing Alarm Details
^^^^^^^^^^^^^^^^^^^^^

Click on any alarm row to view detailed information:

- Full alarm message and description
- Timestamp of first occurrence
- History of state transitions
- Related resource information (Cloud, Instance, Server, etc.)
- Recommended resolution actions (when available)

Alarm Notifications
^^^^^^^^^^^^^^^^^^^

The alarm notification indicator in the |morpheus| header shows the count of open (unacknowledged) alarms. Click the notification icon for a quick summary of recent alarms without navigating away from the current page.

Alarm Resolution
^^^^^^^^^^^^^^^^

Alarms are resolved (closed) in the following ways:

- **Auto-resolution** — When the underlying condition clears (e.g., a Cloud reconnects), the alarm is automatically closed
- **Manual closure** — Administrators can manually close alarms that are no longer relevant
- **Acknowledgment with auto-close** — Some alarm types auto-close after being acknowledged if the condition is transient

Role Permissions
----------------

Access to the Alarms section is controlled by the **Operations: Alarms** role permission:

- **Full** — View alarms, acknowledge/unacknowledge, and manage alarm state
- **Read** — View alarms only; cannot change alarm state
- **None** — No access to the Alarms section

Configure role permissions at |AdmRol| > (Role) > Operations: Alarms.
